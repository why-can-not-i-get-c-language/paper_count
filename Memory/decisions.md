# 技术决策记录

## D001：使用标准外设库

- 状态：已确认。
- 决定：使用 STM32F10x Standard Peripheral Library v3.6.0。
- 原因：项目已按该库建立，且适合当前 Keil 工程。
- 影响：后续代码使用 `GPIO_Init`、`RCC_APB2PeriphClockCmd` 等 SPL 接口，不引入 HAL。

## D002：按层次划分代码

- 状态：已确认。
- 决定：驱动写入 `Hardware/`，计数与标定逻辑写入 `Application/`，主循环保持在 `User/main.c`。
- 原因：便于逐模块测试和定位问题，避免所有代码堆积在主函数中。

## D003：先完成独立验证，再组合功能

- 状态：已确认。
- 决定：按 LED、串口、按键、OLED、测频、标定、EEPROM 的顺序实现。
- 原因：纸张计数依赖多个模块；先验证底层模块可以降低排错难度。

## D004：张数换算使用实测标定表

- 状态：已确认。
- 决定：使用实际纸张测得的频率-张数表，而不是只根据理论电容公式直接计算。
- 原因：纸张湿度、压力和机械间距都会影响电容值。

## D005：版本库包含 SPL 与 CMSIS 源码

- 状态：已确认。
- 决定：首次 Git 提交包含 `Library/` 中当前使用的 STM32 SPL 与 CMSIS 文件。
- 原因：Keil 工程直接依赖这些源码；提交后，新环境克隆仓库即可获得一致的可编译依赖版本。
- 影响：不忽略 `Library/`；仅忽略可重新生成的构建产物、通用依赖目录和本地缓存。
