# 项目实施计划

最后更新：2026-07-26

## 使用原则

- 本计划按依赖关系排序；前一阶段的完成条件未满足时，不进入依赖它的硬件联调。
- “代码完成”“Keil 编译通过”和“硬件已验证”是三个不同状态，记录时不得混用。
- 现已具备母头杜邦线和数字万用表。按键硬件验证可以恢复；涉及 OLED、NE555 和 EEPROM 的实测仍须以器件型号、引脚和供电方式确认完成为前提。
- 每个小阶段结束后，先由用户执行 Keil Build（F7）及适用的硬件测试，再更新 `Memory/progress.md`；用户接受后才进行对应 Git 提交。

## 阶段 0：需求与硬件信息冻结

先做：补齐尚未确认的硬件信息，避免后续驱动因引脚或器件不符而返工。

1. 确认 OLED 驱动芯片、I2C 地址、供电电压和 SCL/SDA 实际连接引脚。
2. 确认 AT24C08 的 A0/A1/A2 接法、写保护脚状态以及与 OLED 是否共用 I2C 总线。
3. 确认蜂鸣器的实际引脚和有效电平。
4. 确认 NE555 到 STM32 的最终输入引脚、频率范围、占空比范围和 3.3 V 电平转换方案。
5. 将最终结果补充到 `Memory/architecture.md`；涉及长期约束的选择补充到 `Memory/decisions.md`。

完成条件：上述信息均已确认，或每个未确认项都有不会阻塞后续开发的临时定义。

## 阶段 1：软件接口与算法基础

现在优先做：这部分不依赖杜邦线，可在当前条件下编写并经 Keil 编译验证。

1. 定义 `app_calibration.c/.h` 的标定点结构、标定表容量、加载/保存接口和查表接口。
2. 实现频率到纸张数量的边界处理、最近点查找和分段线性插值；定义无效频率和超出标定范围时的返回状态。
3. 定义 `app_paper_counter.c/.h` 的输入样本接口、稳定判定、滤波、计数结果和异常状态，不直接访问定时器寄存器。
4. 定义 `app_ui.c/.h` 的页面状态和输入事件接口；暂以串口调试输出表示 UI 状态，不依赖 OLED 驱动。
5. 为关键算法准备固定样本，例如空载、单张、多张、边界值、乱序标定点和异常频率，并通过临时串口输出或独立调用检查结果。
6. 用户在 Keil 执行 F7；编译通过后，更新 `Memory/progress.md` 为“软件逻辑已编译验证，硬件待验证”。

完成条件：三个 Application 模块均有清晰头文件接口，标定与计数算法可在无传感器条件下验证基本样本。

## 阶段 2：按键基础验证

已完成：按键代码已完成真实输入验证，可在后续 UI 中接入按键事件。

1. K1-K4 已分别连接 PB12、PB13、PB14、PB15，另一端接 GND。
2. 已用数字万用表确认未按下约 3.3 V、按下约 0 V。
3. 已完成 F7 编译、下载和 USART1 按键事件验证，LED 运行正常。
4. 后续 UI 可以接入按键事件；若整机联调中出现重复触发或漏触发，再调整消抖策略并重新实测。

完成条件：四个按键均能稳定识别，且不会影响已验证的 LED 和 USART1。

## 阶段 3：I2C 与 OLED 驱动

先实现软件 I2C，再实现 OLED，避免同时排查两层问题。

1. 按阶段 0 确认的引脚实现 `bsp_soft_i2c.c/.h`，提供启动、停止、字节发送、应答和字节接收接口。
2. 先用 OLED 的 ACK 和串口日志检查总线时序；必要时用逻辑分析仪确认 SCL/SDA 波形。
3. 实现 `bsp_oled.c/.h` 的初始化、清屏、字符和数值显示。
4. 显示固定文本、频率占位值、纸张数量占位值和错误状态。
5. 将 `app_ui` 接入 OLED，但保留 USART1 调试输出以便排错。

完成条件：上电后 OLED 可稳定显示状态、频率和张数占位信息，重复复位不出现花屏或总线卡死。

## 阶段 4：NE555 测频驱动

先验证电气安全，再验证定时器测量结果。

1. 完成 NE555 输出至 STM32 输入的 3.3 V 电平转换，禁止将 5 V 方波直接接入 MCU。
2. 根据阶段 0 的最终引脚选择定时器输入捕获或外部计数方案，实现 `bsp_freq.c/.h`。
3. 使用 STM32 已知频率输出回接 PA0，先完成无示波器测频自测；示波器或逻辑分析仪到位后，再检查 NE555 输出波形并与 STM32 报告值对比。
4. 处理定时器溢出、零频率、频率突变和采样窗口不足等异常情况。
5. 将稳定频率样本传入 `app_paper_counter`，但此时不将结果视为真实纸张标定。

完成条件：在预期频率范围内连续测量稳定，已知输入频率的误差和采样周期有记录。

### 波形验证锁定

在示波器或逻辑分析仪到位前，暂停 NE555 波形幅度、占空比、边沿、毛刺、电平转换过冲和传感器噪声的验证。该锁定不阻止驱动编码、Keil 编译、STM32 自测或万用表静态电压检查；但被锁定项不得标记为已验证。

## 阶段 5：标定数据与 EEPROM

先用固定表验证算法，再增加掉电保存能力。

1. 使用实物纸张获取“频率-张数”原始数据，覆盖空载、单张、常用上限和重复测量。
2. 整理标定点，确定是否采用升序频率、分段线性插值和有效范围限制。
3. 实现 `bsp_at24c08.c/.h` 的页写、随机读、写周期等待和地址边界处理。
4. 定义标定表存储格式，至少包括版本号、长度、数据和校验值；实现加载失败时的默认表策略。
5. 执行写入、读回、复位和断电重启测试，确认数据未损坏。

完成条件：标定表可由实际数据生成，且 EEPROM 保存后能可靠恢复并通过校验。

## 阶段 6：纸张计数整合

按数据流集成：测频 -> 稳定判定/滤波 -> 标定换算 -> UI/串口显示。

1. 在 `main.c` 中仅保留初始化和周期调度，将业务处理留在 Application。
2. 接入按键操作：查看计数、进入/退出标定、保存标定表及必要的复位确认。
3. 对纸张逐张增加、逐张减少、快速抽插、停留不动和空载等场景进行测试。
4. 记录误计数、迟滞、稳定时间和环境变化影响，针对结果调整滤波阈值与标定表。
5. 通过 OLED 和 USART1 同时观察关键状态，定位传感器、测频或算法问题。

完成条件：在约定的纸张范围和操作方式下可重复得到可接受的计数结果，异常状态可被识别和显示。

## 阶段 7：验收与交付

1. 汇总最终引脚表、供电与电平转换说明、标定步骤和日常使用步骤。
2. 复测已验证模块：LED、USART1、按键、OLED、测频、EEPROM 和完整计数流程。
3. 更新 `Memory/architecture.md`、`Memory/decisions.md`、`Memory/progress.md` 和交接文档。
4. 检查 `git diff`，仅暂存当前任务文件，创建清晰的本地 Git 提交；除非用户明确要求，不推送远程。

完成条件：用户确认编译和硬件验收结果，项目记录与代码状态一致。
